Progress Report No. 1

1. Group Information

  • Group Number: 12
  • Members: Shawn Veloso, Rev Martinez

2. Project Specifications

  • Chosen Algorithms:
    1. Priority Scheduling (Non-preemptive)
    2. Priority Scheduling (Preemptive)
    3. Multilevel Queue (MLQ). The MLQ has two queues. Queue 1 (foreground) uses Round Robin with a time quantum that the user sets. Queue 2 (background) uses FCFS. Queue 2 runs only when Queue 1 is empty. A new process in Queue 1 preempts a Queue 2 process immediately.
  • Technology Stack: HTML, CSS, and JavaScript, with no frameworks. The simulator runs in a web browser. HTML and CSS show the Gantt chart. The user can upload the process data as a CSV or TXT file. We use Git for version control.

3. Task Delegation

  • Shawn Veloso: Shawn writes the scheduling logic for the three algorithms. This includes the ready queue, preemption, the Round Robin time quantum, and the tie-breaking rules. Shawn also writes the calculation of the completion time, turnaround time (TAT), waiting time (WT), and the averages.
  • Rev Martinez: Rev makes the user interface. This includes the input table, the file upload, and the input validation with error messages. Rev also makes the color-coded Gantt chart. The chart shows idle time and preemption points.
  • Both members: We make test data with edge cases, such as non-zero arrival times, idle gaps, and equal priorities. We calculate the results by hand and compare them with the simulator output. Each member examines the code of the other member. This makes sure that each member can explain all the algorithms during the defense.

4. Accomplishments & Wireframe

  • Current Progress:
    • We formed the group.
    • We selected three algorithms. Two algorithms are preemptive and one algorithm is non-preemptive. This meets the requirement for a group of two members.
    • We selected the technology stack.
    • We wrote the tie-breaking rules before we started to write code:
      • A lower number has a higher priority.
      • If two processes have the same priority, the process that arrived first runs first. If they also arrived at the same time, the lower process ID runs first.
      • A new process preempts the running process only if its priority is higher. An equal priority does not cause preemption.
      • In Round Robin, a new process enters the queue before a process whose time quantum expired at the same time.
    • We examined the project requirements and the grading rubric.
    • We made a local Git repository and the project folder structure.
    • We made the UI wireframe (below).
  • UI Wireframe: The wireframe has four areas:
    1. Simulation settings: the algorithm selection and the time quantum.
    2. Input table: Process ID, Arrival Time, Burst Time, Priority, and Queue. The user can add rows or upload a file.
    3. Gantt chart: a color-coded timeline. It shows process switches, idle time, and preemption points.
    4. Performance metrics: the completion time, TAT, and WT for each process. This area also shows the average TAT, the average WT, and the CPU utilization.
    The sample data uses Preemptive Priority. We checked all the values by hand.
